## 1. P2 · 规则命中率 0 → 3/3

### 症状

3 次真实 run、10 个计划步骤，**0 次**由规则自动完成；全部靠 planner 手工 `mark_step_done`。
`docs/07` 里那句"规则命中率"实际等于 0。

### 为什么原规则不可能命中

原实现：`expected_evidence` 整串做中文 2-gram，覆盖率 ≥60% 判定命中。
而 expected 天然是任务口吻：

```
"拿到 Server 响应头或框架版本标识等服务指纹"
```

动词与虚词（拿到 / 或 / 等 / 服务）占掉一半 token，加上 2-gram **跨词边界**
（"到s"、"r响"、"页u"），真实事实的覆盖率只有 20%~40%。

### 怎么做（先量，再改）

把 3 次 run 的真实 `(step, fact)` 对导出成 NDJSON，离线跑 6 种候选规则（临时程序，
不进仓库）：

| 规则 | 正确 | 误报 | 漏报 |
|---|---|---|---|
| A 现状（整串 2-gram ≥60%） | 4/15 | 0 | 11 |
| B 按 `、，/或` 切子句后取最好子句 | 10/15 | 0 | 5 |
| C B + 去包装词（拿到/确认/证据…） | 10/15 | 0 | 5 |
| E B 或（≥2 个 3 字片段 + 子句覆盖率 ≥35%） | 12/15 | 0 | 3 |
| **F 一个 ≥4 字片段命中，或 ≥2 个 3 字片段命中** | **12/15** | **0** | 3 |
| G ≥1 个 4 字片段 且 ≥1 个 3 字片段 | 10/15 | 0 | 5 |

选 F：它把"任务口吻"绕开了（只匹配句子里的具体名词片段），同时保留"宁漏不误"——
4 个反例（端口扫描 ≠ 指纹步、登录页 ≠ 框架版本步）全部不误报。

实现要点（`store/plans.go: expectedMatches`）：

1. 整串包含 → 命中（最快路径）；
2. 否则切子句，去掉包装词，只在**同一 CJK 段内**取 3/4 字片段；
   ASCII 取 ≥4 字整词（server / nginx / favicon）；
3. 命中 = 任意 1 个 4 字片段，或 ≥2 个不同的 3 字片段。

### prompt 配套（真正的杠杆）

规则再准也救不了"写给人看的整句"。所以同步约束写法：

- planner prompt 与 `add_plan_step` 描述都要求 expected_evidence 写成**判据词条**
  （「Server 头含 nginx；X-Powered-By；版本号 v1.4.2」）；
- 并且要求**每条有区分度**：不写「登录」「表单」「302」这类单位词 ——
  否则任意一条沾边的事实都会满足该步（这是本规则"偏松"的一面的直接补丁）。

### 验证（同一 goal、同一靶场）

| 指标 | 改前 run #20 | 改后 run #22 |
|---|---|---|
| 步骤总数 | 3 | 3 |
| 规则自动完成 | **0** | **3** |
| `mark_step_done` 调用 | 2 | **0** |
| expected_evidence 形态 | 「拿到 127.0.0.1:8080 根路径响应中的 Server 响应头原始值」 | 「Server；X-Powered-By；Set-Cookie；Server 头；nginx；Apache；版本号」 |
| HTTP 请求 / 失败 | 25 / 0 | 27 / 0 |
| 输入 token | 176,723 | 168,306 |
| 结局 | done（2 目标 met） | done（2 目标 met，4 事实） |

**已知代价（写在前面）**：F 规则只能证明"事实里出现了判据的关键片段"，不能证明语义成立。
实测 `run #22` 里同一个响应头事实同时满足了 3 个步骤（其中两步只是"沾边"）。
目标层不受影响（`prove_goal` 仍要求指定 fact），但**步骤的"done"会比过去更容易达成**；
若以后要更严，方向是"子句必须整体命中 + 至少覆盖一半子句"，代价是命中率回落。

## 2. P3 · `confidence=observed` 被用来装推断

### 症状

两次真实 run 都把"**响应里没有 X-Powered-By**"推成"/login 是 nginx 静态文件"，
并且标了 `observed`：

```
fact#93 … /login 落到另一个 handler：… 无 X-Powered-By，且方法无差别响应，
         提示 nginx 上有独立 location 或非 PHP 后端（confidence=observed）
```

同一轮里"POST /login 任意口令都 200 → 登录结果不可区分"正确地标了 `inferred`，
说明模型会用这个枚举，只是**边界没定义**。

### 为什么这是产品问题

证据门槛能挡住"没给证据"，挡不住"证据不支持结论"。报告可信度取决于 `observed`
是否真的等于"看到的字节"，一旦它等于"我推的"，整份报告的置信度就失效了。

### 修法（纯 prompt / 工具描述）

`record_fact` 描述与 worker system prompt 都钉死两档：

- `observed` = 本次**直接看到**的字节 / 状态码 / 响应头 / 命令输出；
- 凡是由「缺失、差异、时序、排除法」推出的（"没有 X 头所以是静态文件"、"版本在受影响
  范围所以可能有洞"）→ 一律 `inferred`，并在 detail 里写清推理链。

### 验证

`run #22` 的 4 条事实：3 条 `observed`、1 条 `inferred` —— 推断那条正是
"/login 对任意输入无差异 → 凭据处理不可观测"，措辞也从断言变成了"未观察到…迹象"。

## 4. 本轮没做

1. **规则命中率没有变成可观测指标**：`satisfied_by_rule` 已在 payload 里，但没有汇总/告警
   （P1-1 要求 >60%，现在只能靠 SQL 捞）；
2. **negation 未处理**：事实文本里的"未找到 X"仍可能命中"X"这条判据；
3. **P4 成本**：`run #22` 仍是 168k 输入换 4 条事实，意图级预算与 http 响应两档返回没做。
