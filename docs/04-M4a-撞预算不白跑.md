## 1. 这一轮解决什么

M3.5 之后系统"会省钱、会拆目标"，但**跑不久**：一次执行撞到 `MaxTurns`/`MaxDuration`
就只剩半句话收场，已识别的结论全部留在上下文里 —— 而上下文会随会话结束丢掉。
这一轮补三件事：

| 交付 | 位置 | 状态 |
|---|---|---|
| 撞预算后的收尾轮：隐藏 `http_request`、注入收尾指令、给 3 轮写回 | `agent/settlement.go`、`agent/settlement_run.go` | ✅ |
| 三层预算的第二层：micro-compact（清旧工具结果）+ 摘要（中段对话压成一段） | `agent/compaction.go` | ✅ |
| `steer_work`：planner 对在跑的 work 实时纠偏（下一次工具调用前生效） | `agent/tool_planner.go`、`engine.SteerWork`、`agent/worker.go` | ✅ |
| 可观测：`outcome.settlement` / `compacted`、planner 结果带 `situation` | `agent/worker.go` | ✅ |
| 配置项（ENV） | `internal/config` | ✅ |

## 2. settlement：把"被掐断"变成"半成品"

### 2.1 触发条件

只有**被掐断**才收尾：

```
reason == max_turns  → 收尾
reason == timeout    → 收尾
reason == done       → 不收尾（已经跑完）
err != nil           → 不收尾（报错不代表有东西可写）
parent ctx 已取消     → 不收尾（暂停/kill 要如实记录，不要拖时间）
```

### 2.2 收尾轮做什么

```
隐藏 http_request（不再往目标打请求）
注入收尾指令（"把已经拿到但没写回的结论逐条写回；保留 evidence；最后一句总结"）
给 SettlementTurns（默认 3）轮，用**独立预算**（默认 2 分钟）
最终 reason 不变 → 引擎照旧把意图落 exhausted
```

**独立预算**是这里唯一容易写错的地方：撞 `MaxDuration` 时 `execCtx` 已经过期，
沿用它收尾轮一轮都跑不了。所以收尾轮用 `context.WithTimeout(parent, Settlement.Timeout)` ——
`parent` 是 work ctx（kill/暂停能打断它），但**不是**那个已经过期的 execCtx。

### 2.3 为什么不改 reason

收尾轮是"把半成品交付"，不是"完成"。如果把它改成 `done`，规划者会以为这条方向已经做完，
不再续派 —— 而事实上它只是"预算用完了"。`exhausted` 才是正确信号（见 `学习.md` 1.4 的终态语义）。

## 3. compaction：让长会话不撞窗口

### 3.1 三层预算各管一段（不能混）

| 层 | 手段 | 在本轮之前的状态 |
|---|---|---|
| 回合/时长 | `MaxTurns` / `MaxDuration` → 收尾轮 | ✅ 本轮补齐收尾 |
| 上下文窗口 | micro-compact + 摘要 | ❌ 本轮新增 |
| 单个工具输出 | `MaxOutput` → 落盘 + 指针 | ✅ M1 已有 |

### 3.2 算法（从便宜到贵）

```
estimate = f(system + 全部消息)          // 不用 tokenizer：CJK 1 字 1 token、其它 4 字符 1 token
if estimate <= window × threshold: 什么都不做

① micro-compact：把"保留窗口之外"的工具结果换成一句标记（保留头 200 字）
   还超？→ ②

② 摘要：老轮次交给模型压成一段（一次调用），保留首条 user 消息 + 最近 KeepRounds 轮
   还超？→ ③

③ 硬阀门：只留最近轮，并把剩余工具结果截断到 2000 字
```

### 3.3 两个必须守住的细节

1. **按"轮"切，不按"条"切**：一轮 = 一条 assistant（可能带 tool_calls）+ 它后面的 tool 结果。
   按条切会留下"孤立的 tool 消息"，OpenAI 兼容端点直接 400。
2. **摘要失败不能让这一轮失败**：摘要是一次额外模型调用，它挂了就退回到 micro-compact 的结果
   （至少压小了一点），而不是把整条意图判成 blocked。

### 3.4 为什么不用 tokenizer

多一个依赖、多一份"和真实模型不完全一致"的不确定性，而压缩只需要"该不该压"这个二值判断，
阈值本身留了 40% 余量。估算函数有单测（`TestEstimateTokensMonotonic`）。

## 4. steer_work：纠偏不打断

### 4.1 语义

```
planner: steer_work(intent_id, message)
   → engine.steerBox[intent_id] 追加（只有该 work 真的在跑才接受）
   → worker 在**每一次工具调用之前** drain 一次
   → 有消息：本次调用不执行，把消息作为 tool_result 交回模型（IsError=true）
   → 模型看到"这次调用被拦下 + 为什么"，自己改道
```

### 4.2 为什么不做成"打断重来"

打断会丢掉已经跑出来的上下文与工具结果；而且"改道"往往只需要一次纠偏，
不需要重跑。这也和 `kill_work` 形成分工：**方向对、打法错 → steer；方向整个错 → kill**。

### 4.3 两个实现注意

1. **必须回一条 `RoleTool` 消息**，否则 assistant 的 `tool_calls` 没有对应结果，下一次调用直接 400；
2. **意图结束后要清空队列**（`unregisterWork` 里删 `steerBox`），否则消息永远没人取，
   而且下一个复用同一 id 的意图会收到上一条的纠偏（id 不复用，但别赌这个）。

## 6. 验收（自动化）

| 用例 | 断言 |
|---|---|
| `engine.TestSettlementWritesBackOnMaxTurns` | `MaxTurns=1`：主循环写 1 条事实，收尾轮再写 1 条；意图落 `exhausted`；收尾轮的 tools **不含** `http_request` 但**含** `record_fact`；过程里能看到「进入收尾轮」 |
| `engine.TestSteerWorkBlocksNextToolCall` | 纠偏在下一次工具调用前生效；被拦下的写入没有落库（事实数不变）；模型看到 `【规划者实时纠偏】`；对不存在的意图返回 false |
| `agent.TestCompactionNoOpUnderThreshold` | 未超阈值 → 一个字节都不改 |
| `agent.TestCompactionMicrosOldToolResults` | 只清老工具结果、**不调模型**、不改变消息条数、最近结果原文保留 |
| `agent.TestCompactionSummarizesAndKeepsPairing` | 摘要进入首条 user；只调一次模型；`tool_call ↔ tool_result` 配对完整 |
| `agent.TestCompactionSummarizerFailureStillCompacts` | 摘要失败 → 退回 micro-compact，不把错误抛给调用方 |
| `agent.TestEstimateTokensMonotonic` | 估计值随长度单调；CJK 至少一字一 token |

## 7. 本轮没做

1. **planner 侧的压缩**：planner 每轮最多 6 回合，且态势每轮重取，压缩收益低；worker 才是长会话；
2. **真正的 tokenizer**：见 §3.4；
3. **流式下的 settlement**：M4c 引入流式后，收尾轮会复用同一个 provider 接口，但"partial stream 的 committed 边界"要一起看；
4. **注入式预算提示**：现在只有"撞到才收尾"，没有"快到上限时提前提醒模型收拢"（下一步可加）。

---

## 8. 坑

1. **收尾轮别复用 execCtx**：撞时长上限时它已经过期（§2.2）。
2. **收尾轮别隐藏写回工具**：只隐藏 `http_request` 这类"继续探测"的工具，否则收尾轮毫无意义。
3. **压缩必须按轮切**（§3.3），否则下一次请求 400。
4. **steer 必须回 tool_result**（§4.3），否则同样 400。
5. **`record_fact` 的入参形状是 `facts[] + intent_id`**，不是顶层 `summary` —— 写测试时最容易踩。
