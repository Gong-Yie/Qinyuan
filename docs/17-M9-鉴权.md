# M9 · 鉴权（Bearer 令牌 + 会话 + CSRF + 角色）

> 背景：M7/M8 把控制台做成了"能暂停任务、审批危险操作、导出带可执行攻击脚本的报告"的东西，
> 而它一直是**裸端口 + 无鉴权**（只靠"只监听 127.0.0.1"这道物理边界）。
> 这一步补上鉴权，并且把"监听非回环却忘了配令牌"变成**启动即失败**。

---

## 1. 威胁模型（先说清楚防到哪）

| 假设 | 对应措施 |
|---|---|
| 控制台绝不能裸奔在 0.0.0.0 上 | `ValidateServe`：非回环 + 无鉴权 → 拒绝启动 |
| 令牌会泄露、要能分级 | `viewer < operator < admin` 三角色；令牌只存 sha256 |
| 浏览器可能被 XSS 偷凭据 | 会话 cookie `HttpOnly` + `SameSite=Strict` |
| 跨站伪造写请求 | CSRF 双提交：`qy_csrf` cookie + `X-CSRF-Token` 头 |
| 有人爆破登录 | 同 IP 5 次失败 / 5 分钟 → `429` + `Retry-After` |
| 凭据不能进日志/库 | 令牌只从 ENV/`.env.local` 读；日志只打数量与角色分布 |

**不防的**（明确写出来，避免误以为万无一失）：拿到 admin 令牌的人可以做任何事（这是"管理员"的定义）；
没有多租户隔离；不信任 `X-Forwarded-For`（反代场景要另行配置真实来源）。

---

## 2. 用法

### 2.1 最小启用（单令牌 = admin）

```powershell
$env:QINYUAN_AUTH_TOKEN = "<至少 16 字符的随机串>"
pwsh -File scripts/go.ps1 run ./cmd/qinyuan serve --addr 127.0.0.1:8787
```

控制台会先出登录卡片；API 调用带 `Authorization: Bearer <token>` 即可。

### 2.2 分角色（推荐）

```powershell
# 多令牌：token:role，逗号分隔；不带 role 的令牌默认 admin
$env:QINYUAN_AUTH_TOKENS = "读令牌...:viewer,操作令牌...:operator,管理令牌...:admin"
```

| 角色 | 能做什么 | 典型持有者 |
|---|---|---|
| `viewer` | 所有 GET（看任务/发现/时间线/报告/台账） | 只读大屏、值班观察 |
| `operator` | viewer + 任务启停/审批/重放事件/CI 导出/同步工单 | 值班工程师 |
| `admin` | operator + **改审批策略与拦截规则**（它们能放宽闸门） | 安全负责人 |

> 判定表只有一处实现：`auth.RequiredRole(method, path)`。
> 规则：策略/规则类写操作 → admin；其余 GET → viewer；其余写 → operator。

### 2.3 其它配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `QINYUAN_AUTH` | `auto` | `auto`（有令牌就启用）/ `on`（没令牌启动失败）/ `off`（对外监听启动失败） |
| `QINYUAN_SESSION_TTL_HOURS` | `12` | 会话时长（1..168）。会话在内存，**重启即全员登出**（这是特性：天然的撤销语义） |
| `QINYUAN_COOKIE_SECURE` | `0` | 反代 + HTTPS 时设 `1`，会话 cookie 只走 TLS |

会话是**滑动续期**但有绝对上限 24 小时（连续使用也不能永久驻留）。

## 3. 实现位置

| 关注点 | 位置 |
|---|---|
| 令牌/角色解析、会话、CSRF、限速、中间件 | `internal/auth/auth.go` |
| 启动自检（非回环必须有鉴权） | `config.ValidateServe` / `config.IsLoopbackAddr` |
| 路由与中间件装配 | `server.Handler()`：`withMiddleware(s.Auth.Middleware(mux), log)` |
| 接线与令牌来源 | `cmd/qinyuan/main.go: buildAuth` |
| 控制台登录卡片 / 401 处理 / 自动带 CSRF | `webui/index.html`、`webui/app.js`（`api()`、`start()`、`doLogin`） |

三个实现细节值得记住：

1. **公开路径只有** `/`、静态资源、`/health`、`/api/login`、`/api/logout` —— 登录页本身必须能加载；
2. **Bearer 不需要 CSRF**：它不是浏览器自动携带的凭据，套 CSRF 只会让 CI 用起来难受；
3. **401 会让控制台弹登录卡片**（不是白屏）：`api()` 统一拦截 401 → `showLogin()`，页面不渲染任何业务数据。

## 4. 验收

`go test ./internal/auth/ ./internal/server/ ./internal/config/`：

| 用例 | 守的是什么 |
|---|---|
| `TestParseTokens` | 空/过短/未知角色/重复令牌 → 启动失败 |
| `TestRoleOrdering` | 角色偏序 + 路径→角色映射（改策略必须 admin） |
| `TestSessionExpiryAndSliding` | 滑动续期、24h 绝对上限、注销立即失效 |
| `TestMiddlewareAuthRoleCSRF` | 401 / 403 / CSRF 三道门（含 Bearer 免 CSRF） |
| `TestLoginRateLimit` | 5 次失败后 429（正确令牌也要等窗口） |
| `TestLoginSetsCookies` | `qy_session` HttpOnly、`qy_csrf` 可读、都 SameSite=Strict |
| `TestServerAuthEndToEnd` | 走真实 Handler：登录 → 读 → 无 CSRF 写 403 → 带 CSRF 写 200 → Bearer 分级 → 登出 401 |
| `TestServerAuthDisabledAllowsAll` | 开发态（回环、无令牌）行为不变 |
| `TestValidateServe` | 非回环 + 无鉴权 = 拒绝启动 |

**手工浏览器实测**（截图 `docs/screenshots/m9-login.png`、`m9-logged-in.png`）：

1. 无 cookie 打开 `http://127.0.0.1:8793/` → 登录卡片，`/api/runs` 401；
2. 输入 admin 令牌 → 仪表盘正常渲染，顶栏出现「退出」；
3. 控制台里 `POST /api/campaigns`（走 `api()`）→ 201（自动带了 CSRF 头）；
4. 同一请求手工不带 `X-CSRF-Token` → **403**；
5. 点「退出」→ 刷新后 `/api/campaigns` 401、登录卡片重新出现。

启动拒绝也实测过：

```
> serve --addr 0.0.0.0:8792（未配令牌）
拒绝启动： 监听 "0.0.0.0:8792" 不是回环地址，但鉴权未启用：请配置 QINYUAN_AUTH_TOKEN=…
```

## 5. 已知限制 / 下一步

1. **没有多用户**：令牌就是身份，没有用户名/密码/审计到"人"；
2. **会话在内存**：多实例部署时各实例各自登录（要么粘性会话，要么改成 DB 会话）；
3. **没有 TOTP/SSO**：对外交付时应该接 OIDC（令牌换会话那一步换成 OIDC 回调即可，中间件不用动）；
4. **`/health` 仍公开**：只暴露 version/ready/db（不含令牌、不含 LLM key）；需要更严可关掉；
5. **没有 IP 白名单**：反代/内网部署时，建议在反代层再加一层来源限制。
