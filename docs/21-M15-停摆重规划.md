# M15 · 停摆重规划（0 意图不再干等 600s 心跳）

> 来源：[`docs/19`](19-CTF1-复盘.md) §4.5 / §7.4：run #41 第 9 轮产出 0 条意图，
> 下一轮要等到 **00:24:56** —— 中间 10 分钟什么都没发生（`heartbeat_seconds=600`）。
> 这次把"死锁"和"正常空轮"分开处理。

---

## 1. 现象与判定

停摆 = **目标未达成 + 没有任何 open/running 意图**。
此时既没有活干、也没有事件会来唤醒 planner，只能等心跳；而 prompt 里明明写着
"停摆时不得产出 0 意图"（`prompt.go` 的 `stopped` 分支）。

| 不算停摆 | 理由 |
|---|---|
| 任务暂停 / 排队 / 终态 | 是人或调度器让它停的，反复唤醒只烧钱 |
| 目标全部达成（无 open goal） | `goalless` 分支会收尾，不需要再规划 |
| 还有 open/running 意图 | 有活干，等 worker 即可 |

判定在 `engine.isStalled`，只做三件事：读 task 状态、`HasOpenGoal`、`HasActiveIntent`。

---

## 2. 策略（有界，不是死循环）

| 阶段 | 等待 | 次数 |
|---|---|---|
| 立即重规划 | 800ms（给 worker 一点领取时间） | 连续 2 次 |
| 短巡检 | `min(2 分钟, 心跳)` | 连续 3 次 |
| 退回心跳 | 正常心跳（默认 600s） | 之后 |

- **任何一次产出意图、任何一次 `notify`（图变了 / worker 结束 / 人工操作）都会把计数归零** ——
  正常任务不会因为偶尔一轮 0 意图就多花钱。
- 每次切换都写一条 `system` activity（`mode=immediate|patrol|heartbeat`），
  控制台能看到"为什么又规划了一轮"，而不是无声空转。
- 决策抽成纯函数 `nextStallWait(stalled, replans, fallbacks, interval)`，可单测。

---

## 3. 为什么不是"给空转轮加退避"

[`docs/10`](10-成本观测与不做退避.md) §3 讨论过"空转轮要不要退避"，结论是不做：
空转轮很便宜（命中缓存），而退避会延迟 `prove_goal`。

那一条针对的是**正常空轮**（有在跑的意图、或在等依赖）。这里说的是**死锁**：
没有在跑的意图、也没有依赖可等，退避只会把"10 分钟什么都不做"变得更久。
两者在 `isStalled` 里被分开：只有死锁才走重规划。

---

## 4. 实测（测试里把心跳设成 1 小时）

```
run #41 的复现：planner 连续返回 0 意图
INFO [planner] 本轮结果 intents=0 met=false
WARN [planner] 探索停摆（没有 open/running 意图）：立即重新规划
INFO [planner] 本轮结果 intents=0 met=false      ← 800ms 后，而不是 1 小时后
WARN [planner] 探索停摆（没有 open/running 意图）：立即重新规划
...
耗时 1.6s 出现第二轮（TestPlannerReplansImmediatelyWhenStalled）
```

---

## 5. 验收

| 用例 | 守什么 |
|---|---|
| `engine.TestNextStallWait` | 未停摆不接管；2 次立即 → 巡检 → 心跳；巡检不快于心跳 |
| `engine.TestPlannerReplansImmediatelyWhenStalled` | 心跳设 1 小时，8 秒内必须出现第二轮，并留下 `探索停摆` 的 system 记录 |
| `engine.TestIsStalledFalseWhenPaused` | 人工暂停时不算停摆，不许反复唤醒模型 |
| 全量 | `go test ./... -count=1` 全绿 |

## 6. 还没做（需要拍板）

1. **模型坚持 0 意图怎么办**：现在只会重问 2 次。更强的做法是"引擎级硬约束"——
   例如本轮没有 `add_intent` 且停摆，就直接用一条兜底意图（"复核现有事实并给出下一步"），
   或者把任务判定为需要人工介入。这会改变"谁来决定派什么"的边界，属于产品决策。
2. **停摆也要算成本**：连续 0 意图的轮次现在仍全价重算（有缓存但仍是钱）。
   如果要，可以在 system activity 里累计 `stall_rounds`，并给任务级预算加一条"停摆轮次上限"。
